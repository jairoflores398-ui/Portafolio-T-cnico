Caso de estudio

Bajo el capó: de JSON a PostgreSQL

Cómo convertí un backend con persistencia en un archivo plano en una API con base de datos relacional, autenticación y transacciones.
// descripción

Este es el backend de la evaluación de Módulo 6 del bootcamp de Alkemy (con una actualización en Módulo 8): una API REST construida con Node.js, Express y Sequelize que administra usuarios y sus pedidos sobre una base de datos PostgreSQL.

// desafío principal

Pasar de una primera versión que guardaba todo en un archivo JSON a un modelo de datos relacional real, sin perder funcionalidad y sumando seguridad: que las contraseñas no quedaran expuestas y que una operación con varios pasos no dejara datos a medio guardar si algo fallaba.

// solución propuesta

Diseñé la relación uno a muchos entre usuarios y pedidos con Sequelize, separé el código en rutas, controladores y modelos, agregué autenticación con JWT y hash de contraseñas con bcrypt, validaciones de datos (email único, largo mínimo de contraseña) y una operación transaccional de creación combinada (usuario + pedido) con reversión automática si algo sale mal.

// herramientas técnicas
Node.jsExpressSequelize PostgreSQLJWTbcrypt PostmanOpenAPI
// aprendizajes
  • Por qué separar rutas, controladores y modelos hace el código más fácil de mantener.
  • Cómo modelar relaciones entre tablas con un ORM en vez de escribir todo el SQL a mano.
  • La importancia de nunca devolver datos sensibles (como el hash de la contraseña) en las respuestas.
  • Cómo usar transacciones para que una operación de varios pasos no quede a medio camino.
// métricas de impacto
  • CRUD completo de usuarios más 3 endpoints adicionales: login, creación combinada usuario+pedido y consulta de pedidos por usuario.
  • 100% de las contraseñas almacenadas con hash, y todas las rutas sensibles protegidas con JWT.
  • La operación combinada usuario+pedido incorpora reversión automática ante error, evitando registros incompletos.
  • API documentada por completo en OpenAPI, importable directo en Postman o Swagger.
// por qué elegí este proyecto

Porque marca el salto de escribir solo interfaces a construir un backend real, donde ya no basta con que "funcione": tiene que ser seguro, ordenado y fácil de mantener. Es el proyecto donde más crecí en este bootcamp.
